# Карта проекта «АИС управления интернет-магазином автозапчастей»

## 1. Назначение системы
Автоматизированная информационная система управления интернет-магазином автозапчастей предназначена для автоматизации торговой и складской деятельности предприятия, осуществляющего розничную продажу автомобильных компонентов и расходных материалов. Система обеспечивает ведение структурированного товарного каталога, поиск и фильтрацию запчастей по категориям и брендам, клиентскую корзину, оформление заказов с транзакционным списанием складских запасов и фиксацией цен, управление статусами заказов, многоформатный экспорт и импорт каталога (JSON, XML, CSV), генерацию аналитических отчетов (PDF, Excel, Word) и мультиязычный пользовательский интерфейс.

## 2. Стек технологий
- Язык программирования: Python 3.10+ (серверная логика, обработка данных, генерация отчетов).
- Веб-фреймворк: FastAPI (микрофреймворк для построения REST API и маршрутизации запросов).
- СУБД: PostgreSQL 15+ (реляционное хранилище данных в третьей нормальной форме).
- Драйвер базы данных: psycopg2-binary (прямое взаимодействие с СУБД через параметризованные SQL-запросы без применения ORM).
- Клиентская часть: HTML5, CSS3, JavaScript (Vanilla JS), Jinja2-шаблоны.
- Формирование отчетов:
  - ReportLab: создание товарных накладных в формате PDF;
  - OpenPyXL: генерация отчетов по продажам в формате Microsoft Excel (.xlsx);
  - python-docx: подготовка сводных аналитических отчетов для руководства в формате Microsoft Word (.docx).
- Безопасность: bcrypt (хеширование паролей), PyJWT (генерация и валидация JWT-токенов доступа).
- Обмен данными: стандартные модули csv, json, xml.etree.ElementTree.

## 3. Модули системы
- Модуль аутентификации и авторизации (`app/routers/auth.py`, `app/services/auth_service.py`, `app/utils/security.py`): регистрация пользователей, аутентификация по email и паролю, выпуск и проверка JWT-токенов, разделение доступа по ролям.
- Модуль товарного каталога (`app/routers/products.py`, `app/services/product_service.py`): выборка товаров с пагинацией, фильтрация по категориям и производителям, поиск по наименованию и модели автомобиля, получение детальной информации о запчасти.
- Модуль корзины покупателя (`app/routers/cart.py`, `app/services/cart_service.py`): добавление запчастей в корзину, изменение количества, удаление позиций, очистка корзины, расчет промежуточной стоимости.
- Модуль управления заказами (`app/routers/orders.py`, `app/services/order_service.py`): создание заказа, заполнение адреса доставки, выбор метода оплаты, просмотр истории заказов и статусов.
- Административный модуль (`app/routers/admin.py`): CRUD-операции над товарами, модерация заказов, управление статусами доставки и оплаты, просмотр сводной статистики и финансовых показателей.
- Модуль импорта и экспорта (`app/routers/admin.py`): потоковая выгрузка и парсинг входящих каталогов в форматах JSON, XML и CSV с валидацией структуры данных.
- Модуль отчетности и аналитики (`app/utils/reports.py`): программное формирование документов трех типов: товарная накладная (PDF), отчет по продажам (Excel), сводный отчет руководителя (Word).
- Модуль интернационализации (`locales/`): поддержка многоязычного интерфейса (русский и английский языки).

## 4. Данные
### Таблицы базы данных:
1. `Role` (роли пользователей):
   - `role_id` (SERIAL, PK);
   - `role_name` (VARCHAR(50), NOT NULL, UNIQUE).
2. `User` (пользователи системы):
   - `user_id` (SERIAL, PK);
   - `email` (VARCHAR(255), NOT NULL, UNIQUE);
   - `password_hash` (VARCHAR(255), NOT NULL);
   - `first_name` (VARCHAR(100), NOT NULL);
   - `last_name` (VARCHAR(100), NOT NULL);
   - `role_id` (INTEGER, NOT NULL, FK -> Role.role_id);
   - `created_at` (TIMESTAMP, NOT NULL, DEFAULT NOW()).
3. `Product` (товарная номенклатура автозапчастей):
   - `product_id` (SERIAL, PK);
   - `name` (VARCHAR(255), NOT NULL);
   - `description` (TEXT);
   - `brand` (VARCHAR(100), NOT NULL);
   - `car_model` (VARCHAR(100));
   - `category` (VARCHAR(100), NOT NULL);
   - `price` (NUMERIC(12,2), NOT NULL, CHECK price >= 0);
   - `stock_quantity` (INTEGER, NOT NULL, CHECK stock_quantity >= 0);
   - `image_url` (VARCHAR(500));
   - `is_active` (BOOLEAN, NOT NULL, DEFAULT TRUE);
   - `created_at` (TIMESTAMP, NOT NULL, DEFAULT NOW()).
4. `Cart` (пользовательская корзина):
   - `cart_id` (SERIAL, PK);
   - `user_id` (INTEGER, NOT NULL, FK -> User.user_id ON DELETE CASCADE);
   - `product_id` (INTEGER, NOT NULL, FK -> Product.product_id ON DELETE CASCADE);
   - `quantity` (INTEGER, NOT NULL, CHECK quantity > 0);
   - `added_at` (TIMESTAMP, NOT NULL, DEFAULT NOW());
   - Уникальный составной ключ: UNIQUE (user_id, product_id).
5. `Order` (заказы покупателей):
   - `order_id` (SERIAL, PK);
   - `user_id` (INTEGER, NOT NULL, FK -> User.user_id);
   - `total_amount` (NUMERIC(14,2), NOT NULL, DEFAULT 0);
   - `discount_percent` (NUMERIC(5,2), NOT NULL, DEFAULT 0, CHECK 0..100);
   - `status` (VARCHAR(50), NOT NULL, CHECK IN ('new', 'confirmed', 'processing', 'shipped', 'delivered', 'cancelled'));
   - `currency` (VARCHAR(10), NOT NULL, DEFAULT 'RUB');
   - `created_at` (TIMESTAMP, NOT NULL, DEFAULT NOW());
   - `updated_at` (TIMESTAMP, NOT NULL, DEFAULT NOW()).
6. `OrderItem` (позиции заказа с фиксацией цены покупки):
   - `order_item_id` (SERIAL, PK);
   - `order_id` (INTEGER, NOT NULL, FK -> Order.order_id ON DELETE CASCADE);
   - `product_id` (INTEGER, NOT NULL, FK -> Product.product_id);
   - `quantity` (INTEGER, NOT NULL, CHECK quantity > 0);
   - `unit_price` (NUMERIC(12,2), NOT NULL, CHECK unit_price >= 0).
7. `Transaction` (финансовые транзакции оплаты):
   - `transaction_id` (SERIAL, PK);
   - `order_id` (INTEGER, NOT NULL, FK -> Order.order_id ON DELETE CASCADE);
   - `payment_method` (VARCHAR(50), NOT NULL, CHECK IN ('card', 'cash', 'online', 'transfer'));
   - `amount` (NUMERIC(14,2), NOT NULL, CHECK amount >= 0);
   - `currency` (VARCHAR(10), NOT NULL, DEFAULT 'RUB');
   - `status` (VARCHAR(50), NOT NULL, CHECK IN ('pending', 'completed', 'failed', 'refunded'));
   - `paid_at` (TIMESTAMP).
8. `DeliveryData` (сведения о доставке):
   - `delivery_id` (SERIAL, PK);
   - `order_id` (INTEGER, NOT NULL, FK -> Order.order_id ON DELETE CASCADE);
   - `address` (VARCHAR(500), NOT NULL);
   - `city` (VARCHAR(100), NOT NULL);
   - `postal_code` (VARCHAR(20), NOT NULL);
   - `phone` (VARCHAR(30), NOT NULL);
   - `delivery_status` (VARCHAR(50), NOT NULL, CHECK IN ('pending', 'in_transit', 'delivered', 'returned'));
   - `estimated_date` (TIMESTAMP);
   - `delivered_at` (TIMESTAMP).

### Индексы базы данных:
- `IX_User_Email` на `User(email)`: быстрый поиск при аутентификации.
- `IX_User_Role` на `User(role_id)`: фильтрация по ролям доступа.
- `IX_Product_Category` на `Product(category)`: фильтрация каталога по типу детали.
- `IX_Product_Brand` на `Product(brand)`: фильтрация каталога по производителю.
- `IX_Product_Active` на `Product(is_active)`: исключение скрытых/деактивированных товаров из выдачи.
- `IX_Order_User` на `Order(user_id)`: получение истории заказов конкретного клиента.
- `IX_Order_Status` на `Order(status)`: выборка заказов по статусам в административной панели.

## 5. Ключевые процессы
1. Формирование заказа:
   - Клиент выбирает товары в каталоге и добавляет их в корзину.
   - Клиент переходит к оформлению заказа, указывает адрес доставки и метод оплаты.
   - Сервер открывает транзакцию СУБД (`BEGIN`).
   - Проверяется достаточность остатков на складе для каждого товара (`stock_quantity >= quantity`).
   - Создается запись в таблице `Order`.
   - Для каждой позиции корзины создается запись `OrderItem` с фиксацией текущей стоимости товара `unit_price = Product.price`.
   - Уменьшается складской остаток: `UPDATE Product SET stock_quantity = stock_quantity - %s`.
   - Создаются связанные записи `DeliveryData` и `Transaction`.
   - Очищается корзина клиента: `DELETE FROM Cart WHERE user_id = %s`.
   - Транзакция успешно фиксируется (`COMMIT`). При любой ошибке выполняется полный откат (`ROLLBACK`).
2. Отмена заказа:
   - Администратор изменяет статус заказа на `cancelled`.
   - Система автоматически выполняет возврат зарезервированных позиций на склад: для каждой записи `OrderItem` увеличивается `stock_quantity` соответствующего товара в `Product`.
3. Экспорт и импорт каталога:
   - Администратор запрашивает выгрузку в формате CSV, JSON или XML.
   - Администратор загружает файл каталога; система производит синтаксический разбор, валидирует обязательные поля и выполняет пакетную вставку или обновление.
4. Формирование аналитических отчетов:
   - Накладная по заказу (PDF): извлечение реквизитов заказа, данных получателя и перечня позиций с итоговой суммой.
   - Сводка по продажам (Excel): агрегация выручки и суммарного количества проданных единиц по каждому товару с сортировкой по доходности.
   - Отчет руководителя (Word): сводные KPI бизнеса (число заказов, выполненных доставок, объем выручки, число клиентов, топ-5 самых продаваемых автозапчастей).

## 6. Роли и сценарии
- Роль «Пользователь» (Клиент): регистрация, вход, просмотр каталога, фильтрация и поиск автозапчастей, добавление товаров в корзину, оформление заказа, просмотр истории и статусов собственных заказов, смена языка интерфейса.
- Роль «Администратор»: полный доступ к каталогу (добавление, редактирование, деактивация автозапчастей), управление заказами и смена статусов, просмотр списка пользователей и управление ролями, экспорт и импорт номенклатуры в JSON/XML/CSV, выгрузка аналитических отчетов в форматах PDF, Excel и Word.
